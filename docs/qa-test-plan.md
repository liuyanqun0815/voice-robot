# 实时语音机器人测试与验收计划（QA Test Plan）

## 1. 文档目标

- 定义生产上线前必须通过的测试范围、用例、门禁与验收标准。
- 覆盖功能正确性、稳定性、性能、可靠性与回归策略。

## 2. 测试范围

- 前端：采集、VAD、字幕、播放队列、打断处理
- 服务端：ASR 编排、幂等提交、LLM/TTS 编排、取消链路
- 端到端：多轮对话、弱网、重连、异常降级

## 3. 测试环境要求

- 浏览器：Chrome（主）、Edge（次）
- 网络：正常网络 + 弱网模拟（延迟、抖动、丢包）
- 日志与追踪：必须开启 `trace_id/session_id/turn_id`
- 压测环境与生产配置一致（或按比例缩放）

## 4. 测试分层与退出标准

### 4.1 冒烟测试（每日）

- 基本问答可用
- 单轮识别/回复/播报完整
- 失败即阻断后续发布

### 4.2 功能测试（每次迭代）

- 通过率 >= 98%
- P0/P1 缺陷为 0

### 4.3 稳定性测试（上线前）

- 24 小时 soak test
- 无内存持续增长和会话状态漂移

### 4.4 性能测试（上线前）

- E2E 首包延迟达到 SLO
- 打断时延达到 SLO

## 5. 核心测试用例

## 5.1 功能类

### TC-FUNC-001 正常单轮

- 前置条件：服务可用，ASR 就绪
- 步骤：
  1. 用户说一句完整话
  2. 观察增量字幕与最终字幕
  3. 等待 AI 回复播报完成
- 期望：
  - 收到 `asr_partial` 与 `asr_final`
  - 仅一次 `turn_committed`
  - 播报结束有 `audio_complete`

### TC-FUNC-002 双端点同时触发

- 步骤：构造前端 `speech_end` 与服务端 endpoint 近同时触发
- 期望：
  - 只允许一次提交成功
  - 另一请求返回 `turn_rejected(ALREADY_COMMITTED)`

### TC-FUNC-003 打断生效

- 步骤：AI 播放中用户插话“等一下”
- 期望：
  - 旧播放在 300ms 内停止（P95）
  - 旧 `generation_id` 不再下发 `tts_chunk`
  - 新轮可继续识别与回复

### TC-FUNC-004 取消后上下文一致性

- 步骤：AI 长回复中途被打断
- 期望：
  - 仅已播放内容进入历史
  - 未播放内容不写入上下文

## 5.2 稳定性类

### TC-STAB-001 弱网抖动

- 条件：增加 RTT、抖动、轻度丢包
- 期望：
  - 会话不崩溃
  - 无同轮重复提交
  - 可恢复继续对话

### TC-STAB-002 ASR 重连

- 条件：中途断开 ASR 连接
- 期望：
  - 前端收到 `asr_reconnecting`
  - 重连后收到 `asr_ready`
  - 后续识别恢复正常

### TC-STAB-003 TTS 单句失败

- 条件：模拟单句 TTS 超时
- 期望：
  - 跳过失败句继续后续句
  - 最终仍可正常结束本轮（`audio_complete`）

### TC-STAB-004 DeepAgent 执行失败降级

- 条件：模拟 DeepAgent（LangChain 智能体）工具调用异常或超时
- 期望：
  - 服务端返回可播报的兜底短句
  - 当前轮次仍可发送 `audio_complete`
  - 不影响下一轮提交与识别

## 5.3 性能类

### TC-PERF-001 E2E 首包延迟

- 指标：用户停说到首段可播
- 验收：
  - P50 <= 900ms
  - P95 <= 1500ms
  - P99 <= 2500ms

### TC-PERF-002 打断时延

- 指标：用户开口到旧播报停止
- 验收：
  - P95 <= 300ms

### TC-PERF-003 同轮重复提交率

- 指标：`turn_rejected(ALREADY_COMMITTED)` 异常占比
- 验收：
  - < 0.1%

## 6. 缺陷分级与处理

- P0：系统不可用、数据错乱、严重串话 -> 立即阻断发布
- P1：核心能力异常（打断失效、重复回复）-> 修复后复测
- P2：体验问题（偶发延迟抖动）-> 纳入迭代优化

## 7. 发布门禁（Go / No-Go）

- 功能用例通过率 >= 98%
- P0/P1 缺陷清零
- 关键 SLO 达标
- 完成灰度预案与回滚演练

## 8. 自动化建议

- 接口回归：事件协议 contract test
- 状态机回归：提交幂等、取消语义单测
- E2E 回归：正常流、打断流、重连流三条主链路

## 9. 参考代码（Python，测试中常用幂等断言）

```python
def assert_single_commit(results: list[str]) -> None:
    committed_count = sum(1 for item in results if item == "turn_committed")
    assert committed_count == 1, "同一 turn 必须且仅允许一次提交成功"
```

## 10. 错误修复建议（高频）

- **重复回复**：检查 `turn_id` 复用与 `commit_turn_once` 原子性
- **打断后仍播报**：检查 `cancel(generation_id)` 是否传递到 TTS 层
- **句尾截断**：检查 `speech_end` 后 `grace window` 是否生效
- **长会话变慢**：检查上下文摘要与历史窗口裁剪策略
